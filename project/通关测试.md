# 魔塔 50 层通关测试

验证日期：2026-11-17。以当前实际运行的 50 层玩法为准；20 层旧提示词只作为背景参考。

## 结论

已证明存在一条从初始生命 1000、攻击 10、防御 10、零金币零钥匙出发的合法通关路线。每步调用游戏真实引擎，未启用作弊。并不保证任意开门或购买选择都能通关。

| 实验 | 结果 | 最终生命 | 攻击 / 防御 |
|---|---|---|---|
| 普通资源 | 通关 | 791 | 378 / 501 |
| 地图钥匙加倍 | 通关 | 6578 | 396 / 537 |
| 禁用祭坛 | 12 层卡住 | 115 | 43 / 43 |

## 修改

- 第 45、46 层：各将主路两扇黄门改为假墙，黄门移到可选支路，保持黄门总数及钥匙少于门的设计；补回 46 层漏放的一把蓝钥匙。首轮机器人曾分别在这两层耗尽钥匙。该结果说明走法会卡住，并非对旧版本无解的穷尽证明。
- 修复撞墙误删已有撤销记录的问题，补上回归验证。
- 校准模拟器：遵循特殊楼梯目标；逐层探索；允许返回未探索的隐藏层；一区不提前预留二区商人的 800 金币；可用炸药处理隐藏层守卫。
- 固化 3774 步路线，由 npm test 使用真实引擎重新回放；另外保留从头规划的 test:simulate。

## 测试方法与复现

在项目根目录运行：

```bash
npm test                   # 引擎、规则、地图结构及固定路线回放
npm run test:simulate      # 从初始状态重新规划并模拟全程
npm run test:no-altar      # 禁用祭坛，预期在第 20 层之前卡住
npm run test:double-keys   # 地图拾取钥匙加倍的对照实验
npm run build             # 生成单文件游戏
```

默认测试中的固定路线包含 3774 个动作。回放从新游戏开始，依次调用真实引擎执行移动、战斗、开门、拾取、交易与道具使用；每步检查动作成功且生命大于 0，最后检查所在楼层为 50、通关状态为真。不会直接赋予通关状态或提升角色属性。

全程规划使用贪心机器人，按可达资源、战斗损失、祭坛和商人安排路线；这是存在可行路线的验证，不是所有走法的穷尽搜索。钥匙加倍实验只改变地图拾取钥匙的数量，禁用祭坛实验禁止祭坛购买。
