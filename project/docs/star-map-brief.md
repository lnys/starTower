# 《星穹塔》地图制作规范（给分层制作者）

依据：`魔塔50层新玩法.md`（以下简称「规格」）。引擎与规则已经写好，**不要修改** `src/game/star/engine.js`、`rules.js`、`data.js`。如发现引擎必须改，停下来在报告里写明，不要自行改。

## 1. 输出文件格式

每个分片写一个 ES 模块，默认导出一个数组，元素是楼层定义：

```js
export default [
  {
    index: 11,                       // 层号
    entry: { x: 1, y: 0 },           // 入口落点（从下层上来、或罗盘传送时站的位置）：必须是空地
    legend: { 1: 'mossBlob', R: 'redCrystal', G: 'guide' },  // 本层实体字符 -> 实体 id
    grid: [                          // 11 行 × 11 列，行 = y（0 在上），列 = x（0 在左）
      'v.Y..3.y..^',
      // …共 11 行
    ],
    events: [                        // 本层事件（§10），可为空数组
      { id: 'f11-guide', floor: 11, trigger: { op: 'talked', npc: 'guide' }, effects: [{ op: 'say', text: '……' }] },
    ],
  },
]
```

- 地形字符只能用：`. # % w ~ * y b r a ^ v`。**地形字符不能作为实体字符**（所以 `y b r a w v` 不能用作怪物字符）。
- 其余字符全部按 `legend` 查实体，`legend` 里的 id 必须存在于 `src/game/star/data.js`（怪物表 `MONSTERS`、道具表 `CONSUMABLES/KEYS/GEAR/HOLD/ACTIVE`、NPC：`guide`、`merchant`、`altar`）。
- 事件效果：`setTerrain{x,y,terrain}`、`addStair{x,y,dir}`、`spawnItem{x,y,id}`、`grantItem{id}`、`say{text}`、`win{}`。
  触发：`talked{npc}`、`enterTile{at:{x,y}}`、`defeated{at:{x,y}}`、`allDefeated{at:[{x,y},…]}`。每个事件只触发一次。

## 4. 每层必须满足（自检清单）

1. **数量**：怪物种类与数量、晶石、药水、钥匙、门，与规格 §9 对应层的表一致。允许药水 ±1、黄门 ±1；全区合计必须一致。
2. **楼梯**：见第 3 节。
3. **主路必须打怪**：入口到上楼梯的每条路上至少有一只怪或一扇门。楼梯四邻不放怪。
4. **主路自给**：只用本层主路上能拿到的钥匙，就能从入口走到上楼梯。主路上最多 2 扇黄门，不放蓝门和红门（区末王座的红门除外）。
5. **支路要有回报**：每扇支路门后面都有东西，不许有空房间。门比钥匙多是有意的。
6. **守卫**：晶石和装备前至少隔着一只怪或一扇门。数值门怪只能堵支路，不能堵主路。
7. **灼域怪**（41 层以后）放在门边或拐角，玩家必须从它旁边经过至少一步。
8. **假墙**：墙后空间在外观上明显多出一块（即周围墙厚度不一致），或有引路人提示。假墙后不放主路。
9. **裂墙**全塔正好 10 处（本分片只负责其中一部分，见分片说明）。
10. **连通**：把门、假墙、裂墙、机关门、熔岩都当作可通过，本层每个空地格、每个实体都必须从入口可达。
11. **BOSS**：按规格 §10 的事件表生成事件（如 10、20、30、40 层的上楼梯生成）。BOSS 的 `allDefeated` 与 `defeated` 事件要写对坐标。
12. **机关门**：每扇 `a` 都必须恰好有一条事件把它改成 `.`（`setTerrain`）。

## 5. 校验

每个分片写完后，运行：

```
node tools/star-check.mjs <你的文件路径>
```

（脚本会检查尺寸、字符、实体计数、连通性；它不检查楼梯和主路，所以你仍要按第 4 节自检。）
